# Persistent message-source backoff

Approved roadmap gap: the bounded producer can revisit the same slow failing source at the start of every run. Use a service-only per-plan admission record, committed before enqueue, so a timeout/crash does not erase the backoff. Initial cooldown five minutes, doubling per claimed attempt to one hour; max counter32. Successful enqueue clears only the exact opaque claim token; stale completions cannot erase a newer claim. Failed/unknown/temporarily ineligible enqueue leaves its cooldown. Discovery omits cooling-down sources and keeps existing eligibility predicates/keyset ordering. Concurrent claims admit one attempt. Already-created outbox events stay idempotent and excluded by discovery. No send eligibility or clinical policy changes.

Private table FK to plan with cascade; RLS with no user access, narrow service RPCs only. Bounded cleanup of records past source eligibility (published >48h ago) can be performed by the existing worker sweep, or retained under FK until a later retention policy; do not invent audit deletion policy. These are scheduling state, not provider outcome records. Prefer bounded cleanup during claim/discovery only if tested.
