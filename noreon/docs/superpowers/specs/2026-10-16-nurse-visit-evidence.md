# Structured nurse visit evidence

Approved bounded slice against28dcdcc and root NURSE_VISIT_INTEGRATION_PLAN.md / NURSE_BOOKING_BOUNDARY.txt. Owner edits only new public schema/component/check/spec. D3 owns persistence, actions, route and snapshot integration. This schema is not authorization.

Public contract is visit-evidence-v1. Keep real-care member id/revision vocabulary, stable server-supplied visitId and submissionId. Open a linked or explicitly unlinked visit, then append factual entries atomically. Entries are partial: omitted produces no row; known includes finite canonical value/unit; unknown includes reason. Standalone pulse and partial BP are finite raw staff evidence, with no new clinical bounds. A complete known BP pair requires existing integer60–300/30–200 bounds, same observed instant and systolic greater than diastolic for exactly-once server projection. Same-instant included pulse must satisfy existing integer20–250 bounds or reject the whole append; different-instant pulse remains raw and separate, never silently attached/dropped. Other fields finite only, no new clinical ranges. Temperature wire C, display°C. Reason/note<=2000; append1–128; no duplicate observation field or collection test. No actor/source/recorded timestamp inputs. Server derives identity and metadata, checks route member and accepted booking/test membership, performs BP projection once in the transaction and hashes history. Never call legacy measurement action in parallel.

Collection disabled without current trusted accepted context, when stale, or when the visit context does not match current accepted appointment/revision. Measurements/notes remain useful. Never use latest proposed revision or infer test links. History retains original test titles/context. No completion, laboratory receipt, device, diagnosis, questionnaire overwrite or clinical-policy claim.

Required injected command/refresh ports have no production fallback. Saved includes exact submission/visit/revision/entries. Invalid is known rejected and editable; stale/access/unavailable need recovery. Thrown/null/malformed result is unknown. Refresh carries the full unchanged frozen command (operation/revision/payload), consistent with member/visit envelope. It never executes that command. Backend must commit a same-key/payload/currentactor terminal retirement fence before authoritative not-recorded, preventing a queued original HTTP command from later executing; serializing a momentary missing-row lookup alone is insufficient. Recovery must serialize against pending command and return committed, definitely-not-recorded (serialized:true), or unknown; arbitrary read-not-found is insufficient. The browser trusts the authenticated action contract, not this flag as independent authority. Frozen payload/key cannot change on unknown or RSC prop regeneration. Receipt identity mismatch remains unknown. New commands require explicit resolved context; actor/member/visit switch clears draft and ignores late results. No storage or automatic retries.

UI uses existing navy tokens, system app fonts, compact fields and48px recovery controls, progressive history/collection disclosure. Start blank, no prechecked collected states. EN/HY375/1280 + enlarged text and error/unknown/unlinked/stale fixture checks are intermediate. Actual nurse→doctor Auth/DB save/reload, immutable provenance, guarded races and source/publication integration remain required D3 acceptance. No services before reserved3195 is free; temporary harness removed and owned runtime stopped at freeze. No DB/provider/CI/push/deploy/real health data.

History per-entry literal-offset dates, actor/provenance and optional exact ISO; same submission never implies shared attribution/time. Counts mean entered, not clinical completion. Source/render independent review and actual persistence remain separate gates.
