# Doctor efficiency and evidence-linked assistance

Draft stage-four design, not approved or implemented. Stage three remains in progress. This draft records code inspection and concrete contracts for Claude design review.

## Intent and scope

Help the doctor move from source checking to clinical review and a published plan with less repeated navigation. Preserve publication safeguards, explicit clinical decisions, and access to full evidence. Implement the accepted stage-four scope: consolidated source review, identity/source assistance, an evidence-linked review brief, and doctor-confirmed result/order associations. Do not change the policy that every imported report needs current approval; historical-report exclusion requires separate clinical agreement and is not assumed here.

## Existing behavior to preserve

`case-summary.ts` already validates structured evidence IDs and rejects provider citations outside that ledger. `case-summary.tsx` fingerprints evidence and hides an old response after evidence changes; retain this protection. The provider is optional, consented, and cannot publish or choose medication. `care-plan-draft.ts` intentionally leaves medication fields unchanged and distinguishes its selected four findings/four historical rows from full evidence. There is no basis to claim these existing protections are absent.

Observed limits: checked report row IDs use report array positions rather than report identity/revision. Selection is capped at 40 findings, 20 BP measurements and 100 rows without a durable source mapping. The brief ledger has row/page text but no direct original-document navigation. The source report/ordered requirement relationship is separate from the current generic received-test command. These are the boundaries to improve, not reasons to rewrite clinical rules.

## Proposed workflow

One doctor review surface lists each report with original-file access, extracted/edited values, report date, printed identity, transcription uncertainty, source-check status and clinical approval. Selecting a cited item opens the exact report and page/row context while retaining draft edits. Do not place source checking and clinical approval behind one ambiguous checkbox.

Identity assistance compares printed identity with the known case locally and conservatively. Differences, missing identity/date and likely duplicate documents are visible suggestions; they never auto-reject an upload, merge records or attest that a report belongs to a person. A doctor explicitly records the source/identity confirmation. Avoid inventing dates from filenames or upload time.

Order association suggestions refer to active requirement IDs, report ID/revision and specific source row IDs. Show ambiguous/multiple candidate matches; changed/retired requirements cannot consume earlier associations. The doctor confirms what was matched and whether the ordered evidence is complete. Partial or ambiguous associations do not silently mark the entire order received. If the codebase lacks an approved definition of panel completeness, use an explicit clinician attestation rather than inventing a required-analyte list. Keep the existing manual receipt route clearly identified as a staff attestation. Association changes must participate in evidence freshness and publication snapshots.

## Evidence model and brief

Create a deterministic evidence ledger with stable IDs derived from report ID, revision and source-row index, or measurement/clinical-rule identities. Each entry carries type, display text, source pointer, date provenance and uncertainty. Separate fictional current fixtures from real uploaded source records. Preserve printed reference ranges as printed ranges, never personalized treatment targets. Comparable trends require compatible marker/unit context; do not invent conversion factors.

A bounded selected brief must disclose included and omitted counts and offer the full ledger. Selection should prioritize changed evidence and current ordered evidence while retaining relevant prior comparable values. Tie the selection to the current case evidence revision. In shared mode the server derives and validates selected IDs against its coherent snapshot, rather than accepting arbitrary client text as authoritative case evidence.

AI output remains an optional unapproved draft. Every clinical consideration references existing ledger IDs. Unsupported/malformed citations fail validation. Missing information stays explicit. Existing approved protocol references remain the only guideline channel; no model-invented guideline links. Provider timeout, disabled configuration or invalid output leaves source review and manual drafting usable. A stale response must not overwrite a doctor's edited draft. AI cannot approve a report, complete a test, decide consultation need, change medication, close review or publish.

## Verification and unresolved details

Before implementation, inspect report-review persistence and receipt/write permissions and specify the exact association schema and SQL protection. Test stable source IDs after report reorder, report revision changes, deleted sources, stale responses, ambiguous/partial matches, duplicate suggestions and identity differences. Verify association changes invalidate draft/review freshness once; verify publication includes the reviewed association provenance and rejected writes preserve prior state. Browser-test original-source navigation, retained edits, manual review with AI disabled, and the consented fictional-provider flow. No live provider calls, new credentials, clinical thresholds or external messaging are assumed by this draft.

## Concrete implementation contract

1. **Source review and identity assistance.** Pass the actual case member name into DoctorReports/ReportWorkspace (it currently passes an empty string). Compare normalized printed and case names locally, flag missing dates/names and exact duplicate extracted content, and display these as advisory checks, never identity proof. Display an authenticated source preview alongside checked fields for supported PDF/images, using the existing staff original-file route with a validated preview flag and unchanged staff/case authorization. Keep download fallback. Source checking and clinical inclusion stay separate actions. The explicit clinical inclusion action states that the doctor has checked identity/source; its existing attributed approval snapshot records the report being approved. No automatic rejection or removal follows a mismatch.

2. **Stable evidence ledger.** Use report ID, server-owned content revision and row index for checked row IDs rather than report array position. Preserve a local-only source map (report ID, page, row index, original URL) and do not send names, file names or raw snippets to AI. Findings retain clinical rule IDs; BP uses measurement IDs; fictional current results retain their explicit fixture prefix. Build the same bounded evidence selection in one pure helper for client and server, with included/omitted counts and a complete on-screen source ledger. Reordering reports cannot change a row ID; changing checked content must. Preserve current caps and disclose omissions; do not let a bounded selection imply a complete review.

3. **Authoritative shared AI input.** Shared case-summary requests include the case evidence revision and the exact consented evidence. The staff route derives the expected evidence from its coherent assigned-case snapshot and rejects stale revision or mismatched content before calling the existing bridge. It forwards only the existing allowlisted case-summary payload, so the bridge/provider contract does not change. Local fictional requests retain their existing explicit consent and client evidence contract. Existing client fingerprinting still hides stale responses. Source links resolve through the local ledger; invalid provider citations remain errors. No new model/provider/clinical guidelines, automatic decision or publication authority is introduced.

4. **Doctor-confirmed order association.** This is source provenance, not panel-completeness inference. Add optional order-association metadata to the report record, each entry containing active requirement ID, selected checked row indices, confirming actor/label/time, and the checked content revision. A narrow service-only SQL command accepts expected case evidence revision, expected database report revision, requirement ID and bounded distinct row indices; it locks case, validates active assigned doctor/clinic, locks report, checks active requirement and confirmed checked rows, and changes only association metadata. It increments report record/database revisions and clears the prior clinical approval. The existing report evidence trigger advances one case revision/task and exact publication coverage changes through report revision/approval. The publication's report snapshot retains associations; no separate untracked mutable table is needed. Changed report contents make earlier associations historical/unverified; retired requirement IDs cannot count as current associations. Clearing a link follows the same locked command. UI separates suggested text-name matches from confirmed links, displays ambiguity and allows manual selection; no approved analyte/panel mapping is invented.

5. **Receipt boundary.** Saving an association does not mark an ordered test received. Keep the existing explicitly labelled staff receipt attestation as a distinct action; partial rows, ambiguous names and historical requirement links never silently satisfy the current order. The consolidated review makes both current missing requirements and their source associations visible, reducing navigation without inventing clinical completeness definitions. These associations are not proof of provider results or member identity.

## Focused verification

Reorder/revision/delete source IDs; full versus selected counts; source preview authorization and download fallback; missing identity/date and duplicate advisories without auto-action; malicious or stale client AI content rejected before upstream fetch; malformed/cross-source AI citations rejected; provider-disabled/manual flow preserved. Association tests exercise actor reassignment/inactive clinic, stale case/report revisions, duplicate/out-of-range row IDs, retired/foreign requirements, report edits after confirmation, old publication retention, one evidence increment, and no receipt side effects. SQL reset/type generation and source-to-member publication coverage regressions remain required. Browser checks use fictional local files only; no live provider invocation is implied.


## Design review resolutions B1–B4

**B1 — content identity.** Add optional server-owned `contentRevision` inside shared report JSON, defaulting legacy records to zero. It changes when extraction or reviewed content (including report date and identity text) changes; association or explanation-only edits do not change it. Row IDs and association content references use this counter, while existing `record.revision` continues to bind approval and database `revision` provides optimistic concurrency. Association writes increment the latter two only. Local fictional report mutations apply the same pure content-revision transition. A changed case evidence revision still invalidates any pending AI response even if row IDs remain stable.

**B2 — protected metadata.** Replace the effective `workspace_write_report` definition in a forward migration. Insert rejects client association/history/content-revision metadata (server initializes it). Generic update requires incoming protected metadata to match stored values (legacy omission normalizes to empty/default) and SQL derives the new content counter. On content change, SQL moves active associations into history with reason `content-changed`, clears active associations and increments content revision. The dedicated association function locks case, validates doctor/clinic and expected case evidence, then locks/checks report and active requirement/row bounds; it alone writes active associations and their attribution. It preserves unrelated record fields, increments record/database revisions, clears approval, and relies on the existing report trigger exactly once. Association removal is recorded as removed history. Existing historical entries are immutable to generic callers. Retired requirement links remain historical context, never receipt proof. Member projection strips staff actor UUIDs from both active and historical associations, including nested published approval snapshots.

**B3 — preview.** Reuse the established verified-account original preview pattern in `app/api/patient/reports/[id]/original/route.ts`: shared staff preview accepts only `preview=1`, revalidates downloaded bytes with `validateFile` (including active/embedded PDF rejection), returns inline allowed PDF/JPEG/PNG with nosniff, private/no-store and `default-src 'none'; frame-ancestors 'self'`. PDFs use browser iframe preview; images use an image element. The ordinary download route retains attachment plus its existing sandbox policy. Case/staff authorization is unchanged. There is no new renderer dependency; failed/unsupported preview leaves an explicit download fallback.

**B4 — consented subset.** Parse strict staff request schemas before upstream fetch. Case-summary envelope contains the existing strict payload plus expected evidence revision and omitted counts. Build a full authoritative allowlisted ledger from the same case snapshot, reject stale revision, and require each submitted evidence item to match an existing authoritative item field-for-field with no duplicate IDs. Validate omitted counts against full counts, category by category. Selection is deterministic (clinical rule ID; measurement time descending with ID tie; report date descending with report ID/content revision/row-index ties), uses no wall clock and keeps fixed caps. The server validates the submitted consented subset rather than assuming its own capped selection is identical. Only the original strict payload reaches the bridge. Parse explain strictly with the bridge's existing consent/locale/reviewed shape; source anchoring for report explanation remains its existing report flow, not a claim of complete case-review validation.

**Other resolutions.** Name-only identity advisories are explicit; no printed DOB extraction is added. Duplicate suggestions compare canonical checked rows plus report date, never filenames. Associations precede clinical inclusion: changing a published association reopens review and requires republication because publication coverage changed; UI explains this. Staff actor UUIDs are excluded from member report projections. Existing doctor display attribution remains. Association storage does not convert partial evidence into a complete panel; receipt remains explicit and separate.

Final design additions: losing confirmed state archives active associations as `unconfirmed`, even with unchanged content; source-content changes take precedence as `content-changed`. The entire extraction/reviewed JSON counts as content, including summary/warnings/date/name and ordered rows. Explanation/association-only edits do not. Shared fixtures will compare TypeScript and SQL transitions for all these cases plus key-order/no-op and confirmed downgrade. SQL also owns the increment of record.revision on generic updates. Preview verification uses available browsers; unavailable Firefox/Safari must be reported as untested rather than inferred passing. Claude's final design verdict permits implementation once these additions are recorded.
