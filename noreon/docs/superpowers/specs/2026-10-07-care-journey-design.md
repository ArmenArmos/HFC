# Connected fictional care journey

## Approved intent
The user selected a complete patient-to-doctor workflow with fictional scenarios; real laboratory, device, SMS and appointment integrations remain deferred. Continue the existing authorized build/test/release task. Show the care model with an understandable mobile UI, rather than disconnected screenshots.

## Experience
A protected `/patient/journey` workspace uses the registered demo profile for context and visibly separates fictional scenario records from the member's questionnaire and measurements. Three scenario cases (routine follow-up, clinician review needed, urgent symptoms) have a patient, doctor and coordinator view. Role switching is a presentation control, not staff authentication. The member dashboard links to this workspace only in demo mode. The existing questionnaire remains functional; current answers can be used as history with missing answers explicitly retained, or presenters can load complete labelled fictional histories.

The connected path is history -> proposed investigations with rule provenance -> doctor-approved tests -> coordinator schedules tests -> fictional results arrive -> doctor edits interpretation and approves recommendations -> approved patient plan -> BP/lab trends, reported medication intake, simulated pill-pack events and follow-up queue. Every action updates the same case. Reading a screen never approves anything. Doctor approval is versioned, and changed history/results invalidate dependent drafts/approvals. Clinical urgency uses the existing registry, never thresholds duplicated in UI. Urgent cases cannot silently take the routine approval path.

## Demo boundaries
Every role has a persistent fictional-demo banner. No actual appointment, notification, emergency call, device upload or physician endorsement is simulated as having really happened. Draft text is labelled scenario draft, never represented as generated by live AI. Medication check-ins are reports, pack opening is a separate signal. Reference intervals and historical readings are fictional fixtures and dated. Coordinator assigns/reassigns the demo doctor and tracks tasks, without clinical approval powers. No real clinical deployment readiness claim.

## Storage and reset
Scenario state is browser-only IndexedDB keyed by the current demo session id, transactionally read/updated to avoid acknowledged-save loss. Change notifications synchronize role tabs; expiry is the existing seven-day session expiry. Reset affects fictional scenario data only. No offline sensitive-data caching, external integrations or new packages. Imported JSON validates its exact structure, known marker ids/units, finite bounded values, valid dates, duplicate handling and limits before modifying state. Repeated receipt does not duplicate results. Show import errors without losing existing results.

## Astra corrections
Render non-emergency registry findings in completed questionnaire summaries; Armenian language ancestry including date-picker portal; label Yerevan timestamps; offer explicit Call 103 link on urgent presentations. Serialize existing cookie-backed demo mutation requests across cooperative tabs with Web Locks, including sign-in/sign-out. If unavailable, fail closed for demo writes with clear feedback; this is cooperative browser serialization, not server CAS.

## Visual direction
Extend Noreon tokens and branded typography: clear next-action cards, restrained teal surfaces, readable chronological timeline, trend charts with legends/units and an accessible data alternative. Patient view emphasizes next action, clinician view evidence and approval status, coordinator view pending ownership. Mobile roles remain operable without wide mandatory tables. English/Armenian controls and clear disabled-action explanations.

## Acceptance
All three scenarios are repeatable and resettable. A doctor edits/approves test plan and interpretation, patient sees only the appropriate published state, coordinator cannot publish clinical content. Results ingest idempotently and show dates/units/trends; scenario readings and medication reports are clearly sourced. Reload and second-tab updates preserve state. Previous Astra bugs have regression coverage. Clinical/token checks, typecheck, lint and production build pass; final Astra review and live browser walkthrough precede release.
